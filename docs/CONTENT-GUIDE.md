# 写故事的人从这里开始（CONTENT GUIDE）

## 三个文件，各管一件事

| 文件 | 归谁 | 里面是什么 |
|---|---|---|
| `game/content.js` | **你** | 所有文字：物件描述、问话、措辞选项、信件、审计行、日程 |
| `game/game.js` | 不要动 | 逻辑：检索、会面、删改、账本、漂移、审计 |
| `game/index.html` | 不要动 | 外壳：画面与样式 |

改文字**只需要改 `content.js`**。改完刷新页面即可。

---

## 一条命令自查

```bash
node tools/game-check.mjs
```

它会**真的把第 1–3 天玩一遍**（28 项检查）。你写完第 4 天之后，它会告诉你哪里
对不上 —— 比如"某题只有 2 个措辞选项"、"drift 忘了填"、"某天的物件 id 在
objects 里不存在"。

## 内容结构（照抄即可）

### 物件

```js
objects: {
  receipt: {
    title: "一张收据",           // 桌上显示的名字
    meta:  "刷卡单 · 背面空白",   // 拿起时第二行小字（来源、日期、材质）
    body:  "<p>正文，可以放 <b>粗体</b>。</p>",   // 它是什么、上面写了什么
    hint:  "一句话：这意味着什么。",               // 玩家读完后的那一下
    birthday: true               // true = 属于"今天要检索的目标"
  }
}
```

**写作要点**：`body` 写**物**，`hint` 写**意**。好用的 hint 都不评价，只指出矛盾 ——
「她说你那天在加班」比「这是一个谎言」好得多。

### 一天

```js
{
  n: 4,
  label: "第 4 天",
  clock: "07:40",
  searchGoal: 2,                       // 要找出几件
  searchObjects: ["contract", "keys"], // 桌上出现哪些（必须都在 objects 里）
  objectsOverride: { contract: { birthday: true } },   // 临时改某件的属性
  meeting: { who: "柯 · 合伙人", questions: [ ... ] },
  redaction: { ... },                  // 可选：这一天才有的删改环节
  letter: { ... },                     // 可选：没信就写 null
  audit: { extra: "审计多打的那一行" },
  nightAdds: { id, label, title, meta, body, hint }    // 可选：当晚桌上多一样东西
}
```

### 一个问题

```js
{ q: "他问你什么（这是他/她说的话，写在引号里）",
  chips: [
    { t: "你的回答", safe: true,  note: "为什么这句安全" },
    { t: "另一句",   safe: false, drift: 8, note: "为什么危险" },
    { t: "第三句",   safe: null,  drift: 4, note: "档案里没有答案时会怎样" }
  ] }
```

**三条硬规则**（违反了游戏会崩或失去意义）：

1. **必须三个选项**，一个 `safe: true`、一个 `safe: false`、一个 `safe: null`
2. `safe: false` 必须带 `drift`（建议 5–15；**15 以上留给真正致命的错**）
3. `note` 写**原因**，不写评价。「他从不用反问句对她说话」✓ ／「这是个坏选择」✗

想让某一题**没有正确答案**（设计上最重要的一种题）：三个选项全用 `safe: null`，
代价各不同 —— 参考第 1 天第 4 题（蛋糕）。

### 删改（一整天才一次的道德题）

```js
redaction: {
  target: "receipt",
  prompt: "一句话把选择摆出来。",
  options: [
    { t: "抹除", drift: -6, gap: 1, log: "账本里记下你做了什么。" },   // 降漂移、留缺口
    { t: "留着", drift: 0,  gap: 0, log: "..." },
    { t: "改叙", drift: -3, gap: 1, risky: true, log: "..." }
  ]
}
```

`gap`（档案缺口）是**只会涨不会消**的数字。设计上它的用途是：让"删掉它"永远不是免费
的 —— 缺口本身会在审计里被念出来。

### 信

```js
letter: {
  from: "无寄件人 · 纸质",
  paragraphs: ["第一段", "第二段", "<b>要强调的句子</b>"],
  choices: [ { t: "撕掉", drift: 4, log: "..." }, { t: "收好", drift: 0, log: "..." } ]
}
```

## 还没写的日子

`content.js` 末尾的 `pendingDays` 里列着第 4–14 天的**标题**（来自
`docs/UNDERSTUDY-DAYS.md` 的日程表）。写完一天就把它的对象从 `pendingDays` 删掉、
把完整的一天加进 `days` 数组。

界面对没写的日子**不会崩**，审计页会直接写「（待人工撰写）」。

## 写作基调（这几条决定了它是不是一部好作品）

1. **不解释谁在控制一切。** 政策没有作者，产业没有恶人，只有流程。
2. **不惩罚说真话。** 说真话的代价是**社会性的**（小满会沉默、叶芝不看你了），
   不是数值惩罚。
3. **让"对方记得的版本"和"事实"打架。** 这是本作的核心谜题类型 ——
   正解常常是对齐**记忆**，而不是对齐事实。
4. **恐怖藏在精确里。** 时间戳、编号、百分比、条款号。系统从不咆哮，它只是记录。
5. **每次温柔都要有代价。** 你越像一个好人，你越不像他。
6. **不要写"他其实是个坏人"这种反转。** 原件是**跑掉的人**，不是恶棍；
   把他写成一个和你一样害怕的人，故事才有分量。

---

## 两个数字的含意（写 drift 时心里要有数）

| 数值 | 意思 |
|---|---|
| **30%** | 第一道坎：验证者开始**反问**你（柯会套话、叶芝会看你的手） |
| **65%** | 第二道坎：**账本上的字迹换手** —— 玩家会发现自己在用别人的字说话 |
| **100%** | 清除：一份用敬语写的审计报告，然后四秒静音 |

所以第 1–14 天（第一幕）的累计漂移**建议不要超过 40%**：把大额代价留给第 37 天那类
不可回避的抉择。

---

## 附：写第 4 天的最短路径

1. 在 `objects` 里加 1–2 件新东西（比如"一份改了第 7 条的合同"）
2. 从 `pendingDays` 删掉 `4`
3. 往 `days` 数组追加一天，`searchObjects` 用新 id + 已有的 id 混搭
4. `meeting.who = "柯 · 合伙人"`，三个问题，每题三个选项
5. 跑 `node tools/game-check.mjs` —— 它会把你的第 4 天也走一遍
