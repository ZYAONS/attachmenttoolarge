# attachmenttoolarge — 赛博恐怖解密游戏设计纲要

一份可执行的设计文档，不是灵感清单。每一条都尽量落在**仓库里已经存在的东西**上，
因为能复用就不必从零造。

---

## 1. 一句话

> **一封 24.7 MB 的邮件永远送不出去，而你在一栋没有尽头的办公楼里，替它寻找出口。**

玩家扮演一个今晚必须把文件送到对面的人。**上限是 20 MB。十九点五十九分。**
你要在这个数字面前活下来。

## 2. 恐怖从哪来（这是全篇最重要的一节）

不要做跳吓、不要做追逐鬼怪。这个题材的恐怖来自**官僚基础设施的冷漠**：

| 恐怖源 | 具体表现 |
|---|---|
| **精确的数字** | 20 MB、24.7 MB、0x80040610、550 5.3.4。数字从不解释，也从不改变 |
| **礼貌的拒绝** | 退信永远是敬语："请将文件放在共享位置并发送链接。" 系统不恨你，它只是不为你改变 |
| **政策的年龄** | 「这条策略比我们两个加起来都老」——没人知道谁定的，也没人能改 |
| **循环的时间** | 每次失败后时钟回到 19:59。玩家会先怀疑游戏 bug，再怀疑自己 |
| **制度性的人称** | 走廊里的声音永远用被动语态："该请求已被拒绝。" 没有主语，没有责任人 |
| **空的容器** | 收件箱是满的，里面全是"无"；发件箱是一座坟场 |

**一句可以直接当台词的话**（来自我们的歌）：

> The policy is a stone. And what a stone decides is what a stone decides alone.

## 3. 核心机制：把 CLI 做成玩法

仓库里那六个真实工具（`att-split` / `att-join` / `att-info` / `att-limits` / `att-ndr` / `att-share`）
不只是道具 —— **它们就是解谜动词**。玩家在游戏内置终端里真的敲这些命令，真的看到分割出的
分片文件和 SHA-256。这不是假装的黑客界面：命令会真的执行（WebAssembly 或本地 sidecar）。

### 动词表（每个动词对应一类谜题）

| 命令 | 玩法动词 | 典型谜题 |
|---|---|---|
| `att-split` | **切分** | 把 24.7 MB 切成 6 片；但分片名有规律，而某些邮件网关会拦截特定命名 |
| `att-join` | **重组** | 收齐分片、校验哈希；**有一片是坏的**，玩家要找出是哪一片 |
| `att-info` | **体检** | 探测文件的真实大小/类型；扩展名撒谎，真实类型才是关键 |
| `att-limits` | **查规则** | 7 家服务商的上限与校验日期。世界物理就写在这里 |
| `att-ndr` | **翻译** | 把 550 / 552 / 0x8004210B 翻译成人话 —— 也是**对话系统** |
| `att-share` | **绕路** | 起一个带过期时间和下载次数的一次性链接；有代价 |

### 三条铁律（设计约束，别破坏）

1. **上限不能改。** 玩家永远不能"升级配额"。这是世界的物理定律。
2. **不能骗系统。** 改扩展名、改显示大小都不行 —— 但**可以改文件本身的结构**。
3. **每次绕路都有代价。** 共享链接会过期、会被人先下走、会留下日志。

## 4. 七道谜题（递进，每道教一个新动词）

1. **壁** —— 直接把 24.7 MB 发出去，收到 550 5.3.4。教玩家：读退信。
   解法：`att-ndr` 翻译那串码，发现是"固定上限 20 MB"。
2. **切** —— 用 `att-split` 切成 6 片发出去。教玩家：分片与命名。
   反制：对面拒收"看起来像可执行文件"的附件，玩家要改分片策略。
3. **缺** —— 对面说"第 4 片没到"。教玩家：校验哈希、找出损坏的那一片。
   **恐怖点**：第 4 片在本地也不见了，但哈希显示它"曾经存在过"。
4. **谎** —— 某片扩展名是 `.txt`，真实类型是别的。教玩家：`att-info` 与信任问题。
5. **规** —— 目标服务商的上限不是 20 而是 25，但**校验日期是两年前**，且这一条
   在数据库里被划掉了。教玩家：规则会腐烂。**这一关没有正解，只有后果。**
6. **绕** —— 用 `att-share` 起一次性链接。链接在玩家自己的终端里被**别人**访问了。
   教玩家：便利的代价。
7. **墙后** —— 把所有分片送到，对面回信："收到。但这不是我要的文件。"
   **结局分歧**：文件在传输中被逐片重写，内容已不是原来的内容。玩家要么承认，要么
   从第一片重新开始 —— 而时间**已经**回到 19:59。

## 6. 一个关键的反直觉设计：让"等待"可玩

人们恨进度条卡在 99%。**把这件事做成核心交互**：

- 有一个真实推进的进度条，**永远停在 99%**
- 百分比本身是谜题线索（99.4% 与 99.6% 的差别有意义）
- 玩家可以在等待时做别的事，但**离开房间进度条会退回**
- 恐怖点：某一次它到了 100%，然后**邮箱里什么都没有**

## 7. 技术选型（保持离线可跑，和站点一致）

| 方案 | 说明 |
|---|---|
| **推荐：Godot 4** | 2D/UI 强、Web 导出可嵌入网页版、独立安装包小；终端 UI 用 RichTextLabel 就够 |
| **或：纯 Web（现有技术栈）** | 复用整站 CSS/JS；工具用 Emscripten 编译成 WASM，或做成"本地后端 + 网页前端"（仓库里已有 `server/server.mjs`） |
| **CLI 内核复用** | `att-tools` 那六个工具是零依赖 Node 脚本，**同一份源码**可编译成 exe（已在 Release）与 WASM，玩法与真工具不会分叉 |
| **存档诚实性** | 存档文件本身就是**分片**：玩家可以真的把 `save.att-001..006` 拷到别处、手动重组。这是元游戏 |

## 8. 垂直切片（建议先做这些，两周量级）

1. **一间房**：只有办公桌、终端、一个卡在 99% 的进度条
2. **一条命令**：`att --attach` 失败 → `att-ndr` 读出 550 5.3.4
3. **一次切分**：`att-split` 真的产出 6 个文件，玩家要手动把它们拖进邮件窗口
4. **一个循环**：失败后时间回到 19:59，**但环境有细微差别**（便利贴多了一张、椅子转了个方向）
5. **一首曲子**：循环氛围音乐 + 失败瞬间的主题

做完这五样，"这游戏能不能成"就有答案了。

## 9. 不要做的事

- ❌ **不要跳吓**。这个题材的恐怖是**制度性的**，惊吓会把气质砸碎
- ❌ **不要解释"是谁在控制一切"**。政策没有作者 —— 这是整个设定的支点
- ❌ **不要让玩家赢**。可以让玩家**通过**，但不能让玩家**战胜上限**
- ❌ **不要做成"黑客模拟器"**。终端不是装饰：命令必须真执行、真产出、真失败
- ❌ **不要放血**。全是荧光灯、地毯、纸、以及一个永远礼貌的系统

## 10. 名字与元层

游戏名就叫 **attachmenttoolarge**。现成的元层设定可以直接用：

- 那个"学会"（The Attachment Too Large Society）在游戏里是**幸存者互助组织**，
  规章就是站点上那四条规矩（真实、可核对、不推销、不制造）
- 网站与游戏的**时间线共享**：2026-09-13 19:59
- 七个音轨 = 七章；每通关一章，唱片页上对应曲目"解锁"（网页与游戏互相是对方的彩蛋）
